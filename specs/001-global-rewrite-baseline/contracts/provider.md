# AI provider adapter V1 — Flowise initial, real integration BLOCKED

ConstitutionII requires initial Flowise support behind neutral AnswerProvider and
Classifier ports. This draft preserves that requirement; it does not authorize a
replacement, self-maintained fork, deployment or weakening privacy.

## Blocking evidence

Upstream is archived/EOL; ordinary non-streaming Prediction persists question and
answer. [Maintainer announcement](https://github.com/FlowiseAI/Flowise/discussions/6727),
[pinned persistence implementation](https://github.com/FlowiseAI/Flowise/blob/9291856d1ea4a4ceea9f8fef8ce14f4f6c81e8eb/packages/server/src/utils/buildChatflow.ts).
No emptyhistory/session trick or post-request deletion establishes no-storage.
Real requests remain DISABLED until maintained security ownership and actual
transient-only processing agreement/configuration/technical proof pass review.
Actual endpoints/regions/subprocessors/models/retention are UNKNOWN. No live inspection now.

## Input/output contract

Only necessary currenteligibletext/caption and live own eligibleconsentedcontext.
Use reviewedoperator config/chatflowID, not a chat-suppliedURL or arbitraryoverride.
Localized processing notice is distinct from optional localhistory consent; group
enablement is not membertextstorage consent. Borrowed exchange/derivedanswer stays
transient unless every contributing owner/source qualifies. No persistentprovider
sessionreferences, rawdiagnostics, durablequestion/answer/classification/trainingreuse.

Answer result is bounded transient plain text, typedfailure/configrevision; provider
output cannot authorize, selectscope, chooseendpoint or trigger tools. Drop echoed
question/session/tool/source/diagnostic fields unless separately approved.
Classifier requires exactAD/NOT_AD+finite0–1numericscore; invalidboolean/string/missing/
NaN/infinity→UNKNOWN. Fewshots0–50(default10) only approved tenantprovenance and expiry.
No binarydownload/OCR/transcription/URLfetch/RAG/tool-capableflow is implicitly in scope.
[Prediction API](https://docs.flowiseai.com/api-reference/prediction).

Every providercall checks current access/feature/privacy/generation/scope/quotas;
late results recheck before store/Telegrameffect. No DB transaction duringrequest.
Deadlines/pools/retries are finite in operations.md; ambiguousPOST execution is not
confirmednonexecution. No silent provider/regionfallback or automatic repeat with
a new session after uncertainty. Typedproviderfailure never leaks rawpayload.
